🔧 各ツールの役割

Obsidian

  • ノートの作成・編集
  • 双方向リンクで知識を接続
  • グラフビューで全体俯瞰
  • Git プラグインで自動同期

Cursor

  • AI による情報整理・構造化
  • タスク管理の自動化
  • スクリプト実行・API連携
  • ドキュメント・資料生成

GitHub

  • バージョン管理（履歴保全）
  • 複数端末間の同期ハブ
  • クラウドバックアップ

sequenceDiagram participant U as 👤 ユーザー participant O as Obsidian participant G as GitHub participant O2 as Obsidian（別端末） U->>O: ノートを編集 Note over O: 5分ごとに自動バックアップ O->>G: git commit + push（自動） Note over G: 変更を保存 O2->>G: git pull（自動 / 起動時） G->>O2: 最新のノートを取得 U->>O2: 別端末でも最新状態で作業

🧠 「第二の脳」AI運用ルール（.cursorrules）

会話開始フロー（必須ヒアリング）

Cursorは新しい話題・作業を始める前に、必ず以下を確認してから動き出す：

1
何についての話か？

壁打ち / 要件定義 / 開発 / 振り返り / その他

2
どの事業部/PJに関連するか？

HD / AXIS-Ads / AXIS-PR / WEEVA / FanMarketing / Clay

3
読み込むべきコンテキストの確認

20_Context/{事業部}/ や 30_Projects/{PJ名}/ を読み込むか確認

4
ユーザーの確認を得てから読み込み開始

勝手に進めず、必ず承認を取る

出力ルール

  • 推測・創作を禁止。不明点は必ず TODO: を残す
  • 事実と解釈を分離。解釈を書く場合は Assumption: と明示
  • 新規ノート作成時は必ず該当テンプレートを使用
  • 全ノートにYAMLフロントマターを必須
  • 不明点は勝手に埋めず、必ず質問する

開発モード

実装・デバッグ・デプロイ時は以下を常に参照した状態で進める：

  1. コンテキスト — 20_Context/{事業部}/ 前提情報
  2. 要件定義 — 30_Projects/{PJ}/ 内の要件
  3. 技術要件 — System_Spec.md or technical-spec.md
要件を勝手に変更しない / デプロイ前は必ずユーザー確認 / 進捗は 30_Projects に随時ログ
